# نموذج الأمان

## أصول يجب حمايتها

- أسرار مزودي النماذج وبيانات اعتماد GitHub والخوادم.
- محتوى المستودعات والبيانات التي قد يقرأها أي وكيل مستقبلًا.
- قرارات البشر وسجل الموافقات والتغييرات.
- سلامة بيئات الإنتاج والأنظمة المالية.

## التهديدات الأساسية

- تعريف وكيل خبيث أو تعليمات prompt injection في محتوى خارجي.
- توسيع صلاحيات غير مقصود أو تسريب سر عبر السجلات.
- تنفيذ أوامر أو كتابة تغييرات دون مراجعة بشرية.
- وصول غير مصرح به إلى مستودع أو خادم أو خدمة مالية.

## الضوابط الحالية

- لا يوجد تنفيذ للوكلاء أو اتصال خارجي في النسخة الحالية.
- الوضع الافتراضي `disabled`؛ ويرفض المدقق أي وكيل يطلب `enabled: true` مع هذا الوضع.
- يطابق المدقق حقول تعريف الوكيل وحدود أطوالها ونمط معرّفها، ويرفض الحقول أو الصلاحيات غير المعروفة والتكرار.
- يتحقق المدقق من اتساق صلاحيات كل وكيل مع قائمة السماح في السياسة، ويمنع إزالة محظورات التنفيذ والأسرار والمعاملات المالية والدمج والحذف والنشر.
- موافقة بشرية مطلوبة في كل تعريف وسياسة.
- CI يأخذ صلاحية قراءة المستودع فقط، ولا يمرر أسرارًا.
- الاختبارات محلية وحتمية ولا تعتمد على شبكة.

## متطلبات قبل أي تشغيل مستقبلي

1. تحديد مالك النظام ومراجعين اثنين على الأقل للسياسات الحساسة.
2. تقييم كل مصدر بيانات كمدخل غير موثوق، خصوصًا محتوى Pull Requests والصفحات الخارجية.
3. عزل التنفيذ في بيئة مؤقتة مع حدود CPU/ذاكرة/وقت وشبكة مغلقة افتراضيًا.
4. حفظ الأسرار في GitHub Secrets أو مدير أسرار مناسب، ومنح أقل نطاق ممكن وعدم طباعتها.
5. فرض موافقات بشرية على أي كتابة أو اتصال خارجي أو نشر.
6. إضافة اختبارات إساءة استخدام، سجل تدقيق، وخطة إيقاف قبل تشغيل تجريبي.

## الإبلاغ عن ثغرة

يرجى عدم نشر تفاصيل ثغرة غير معالجة في Issue عام. راجع `SECURITY.md` لقناة الإبلاغ المتاحة.
